# Сервер для Serpium

Этот комплект позволяет позже подключить свой VPS без изменения кода Serpium.
Сервер выдаёт стандартный ключ; пользователь вставляет его в «Мои ключи» и нажимает
«Подключиться». Приложение сохраняет профиль в защищённом хранилище, проверяет
соединение и использует существующие правила приложений и сайтов.

Два режима:

| Режим | На VPS | Ключ для Serpium |
|---|---|---|
| `outline` | sing-box с Shadowsocks ChaCha20-IETF-Poly1305 | `ss://`, совместимый с обычными ключами Outline |
| `reality` | Xray с VLESS/REALITY и Vision | `vless://` |

Режим `outline` — совместимый сервер Shadowsocks, а не установка Outline Manager.
Если VPS уже настроен через официальный Outline Manager, достаточно взять его
обычный `ss://` ключ и вставить в Serpium: этот комплект на таком VPS не нужен.
Адрес панели управления Outline, API-секрет и пароль SSH в приложение не вводятся.

## Что потребуется позже

- Отдельный Linux VPS, например Ubuntu 24.04, публичный IPv4 и доступ по SSH.
- Python 3.10 или новее; внешние Python-пакеты не нужны.
- [Docker Engine и Compose plugin](https://docs.docker.com/engine/install/ubuntu/).
- Разрешённые входящие порты в сетевом экране хостинга. Outline по умолчанию
  использует TCP **и** UDP 20000 для первого пользователя, 20001 для второго и т.д.
  REALITY использует общий TCP 443. UDP приложения передаётся внутри туннеля VLESS.
- Для REALITY — подходящее публичное TLS 1.3 имя в `--target`; его доступность
  проверяется с VPS перед применением. Это отдельная настройка сервера, не ключ пользователя.

Комплект не изменяет SSH и системный firewall, не покупает сервер и не открывает
панель администратора в интернете. Для работы не требуется собственный драйвер Windows.
Выполняйте все команды на VPS от одного административного пользователя.

## Быстрый запуск Outline-совместимого сервера

Скопируйте папку `Server` на новый VPS и перейдите в неё. Вместо `SERVER_IP`
укажите публичный IP или DNS-имя этого VPS:

```sh
python3 serpium_server.py init --mode outline --host SERVER_IP --user owner
python3 serpium_server.py apply
python3 serpium_server.py export --user owner
cat ~/.serpium-server/exports/owner.txt
```

Первая команда создаёт случайный ключ и проверяет конфигурацию. Docker скачивает
официальный образ, закреплённый по SHA-256, если его ещё нет. `apply` запускает сервер.
Последняя команда показывает **секретный клиентский ключ**; передайте его владельцу
по защищённому каналу. В Serpium: «Мои ключи» → `+` → вставить ключ → «Подключиться».

Проверяйте именно открытие сайтов через выбранное приложение из нужной сети.
Старт контейнера не доказывает доступность из России или отсутствие блокировок.

## Вариант VLESS/REALITY

На отдельном новом сервере/каталоге состояния:

```sh
python3 serpium_server.py init --mode reality --host SERVER_IP --target TLS_HOSTNAME --user owner
python3 serpium_server.py apply
python3 serpium_server.py export --user owner
cat ~/.serpium-server/exports/owner.txt
```

`TLS_HOSTNAME` должен поддерживать TLS 1.3, HTTP/2 и X25519; выбирается с учётом
доступности из VPS. Генератор создаёт отдельную серверную ключевую пару REALITY.
В клиентский ключ попадает только публичная часть. Не заменяйте режим существующего
сервера повторным `init`: он специально откажется перезаписывать ваши ключи.

## Пользователи и отзыв доступа

```sh
python3 serpium_server.py add --user friend
python3 serpium_server.py apply
python3 serpium_server.py export --user friend

python3 serpium_server.py rotate --user friend
python3 serpium_server.py apply
python3 serpium_server.py export --user friend

python3 serpium_server.py revoke --user friend
python3 serpium_server.py apply
```

`add`, `rotate`, `revoke` сначала готовят и проверяют новую конфигурацию.
**Отзыв или смена ключа вступает в силу только после успешного `apply`.**
`apply` пересоздаёт контейнер: старые соединения закрываются, остальные пользователи
должны переподключиться. В Outline-режиме для новых пользователей нужно разрешить
новые TCP/UDP порты хостинга. `list` показывает имена и порты без секретов.
`export` создаёт файл только для указанного пользователя, общего публичного списка ключей нет.

При ошибке проверки работающий сервер не затрагивается. При ошибке запуска
выполняется попытка возврата к последней успешно применённой конфигурации.
Если откат тоже не удался, команда сообщает об этом и не объявляет сервер рабочим.
При откате восстанавливаются и прежние права доступа — учитывайте это при отзыве ключа.

## Обслуживание

```sh
python3 serpium_server.py check
python3 serpium_server.py list
python3 serpium_server.py endpoint --host NEW_SERVER_HOSTNAME
python3 serpium_server.py apply
python3 serpium_server.py export --user owner
python3 serpium_server.py stop
```

`endpoint` обновляет адрес в выдаваемых ключах; после смены IP без постоянного DNS-имени
пользователям нужно импортировать новый ключ. Ранее импортированный профиль сам по
себе не является подпиской. HTTPS/`ssconf://` в текущем Serpium импортируются снимком;
при изменении содержимого ссылку нужно импортировать заново. Автоподбор Outline
получает свежий источник при каждом новом подключении.

`stop` останавливает только контейнер этого комплекта, сохраняя ключи и историю.
Состояние хранится в `~/.serpium-server`; другой путь задаётся глобальным `--state`,
но имя последней папки должно оставаться `.serpium-server`. `CURRENT` — подготовленная
ревизия, `DEPLOYED` — последняя успешно применённая. `list` не заменяет проверку
текущего состояния Docker. После перезагрузки Docker запускает контейнер автоматически.

## Секреты и обновления

- На Linux каталог состояния доступен только владельцу; на Windows устанавливается
  ACL текущего пользователя. Содержимое на сервере не зашифровано: серверу нужны ключи
  для работы. Резервную копию следует хранить зашифрованной.
- В истории ревизий остаются прежние секреты для отката. Никому не передавайте весь
  каталог состояния или его архив. Для пользователя предназначен только его экспорт.
- Контейнер работает без root и Linux capabilities, с файловой системой только для
  чтения; монтируется только конфигурация, без базы управления и Docker socket.
- Доступ через прокси к приватным сетям и metadata-адресам блокируется конфигурацией.
  Это не замена ограничениям облачного firewall и учёту трафика у хостинга.
- Рабочие серверные ключи не входят в Git и publish приложения. В комплекте нет
  готовых паролей, идентификаторов пользователей, IP вашего VPS или ключей API.
- `images.lock.json` содержит точные версии и digest официальных контейнеров.
  Обновления сервера выполняются отдельно после проверки совместимости; обновление
  компонентов в Serpium не меняет VPS автоматически. Перед заменой lock-файла
  сохраните защищённую копию состояния и выполните проверки на отдельном сервере.

## Проверки разработчика

На Windows можно готовить конфигурации с точной локальной версией движка:
глобальный параметр `--engine-binary <путь к exe>` заменяет Docker при подготовке.
`apply` и `stop` работают только на Linux и всегда используют закреплённые контейнеры.

```text
python Tests/Server/test_server.py <папка результатов>
dotnet run --project Tests/Server/ServerChecks.csproj -c Release -- <папка результатов> bin_files/relay
dotnet run --project Tests/Outline/OutlineChecks.csproj -c Release -- <другая папка результатов> bin_files/relay/sing-box.exe
```

Тесты используют искусственные ключи и отдельные локальные процессы; VPN-маршруты
Windows и пользовательские профили не изменяются. Проверяется реальный обмен
Shadowsocks и VLESS/REALITY, а Docker-развёртывание/откат проверяется подставными
вызовами. Проверка Linux Docker и доступности выбранного VPS из России остаётся
этапом запуска, когда VPS будет предоставлен.

Протоколы: [Shadowsocks в sing-box](https://sing-box.sagernet.org/configuration/inbound/shadowsocks/),
[Xray REALITY](https://xtls.github.io/config/transport.html),
[официальный Outline Server](https://github.com/OutlineFoundation/outline-server).
