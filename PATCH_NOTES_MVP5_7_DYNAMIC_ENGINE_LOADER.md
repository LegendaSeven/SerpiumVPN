# SerpiumVPN MVP5.7 — Dynamic Engine Loader

## Что добавлено

- автоматическое сканирование runtime-папки `Engines`;
- загрузка каждого движка из отдельной подпапки с `manifest.json`;
- проверка версии схемы манифеста и Engine API;
- загрузка DLL через отдельный `AssemblyLoadContext`;
- общий тип `IEngine` остаётся из основной сборки SerpiumVPN, без конфликта типов;
- автоматический поиск реализации `IEngine` или выбор через `entryType`;
- автоматическая регистрация найденного движка в `EngineRegistry`;
- защита от повторной загрузки одинакового `id`;
- защита от выхода пути DLL за пределы папки движка;
- ошибка одного движка не роняет запуск всей платформы;
- результаты обнаружения доступны через `PlatformRuntime.LastEngineDiscovery` и `PlatformRuntimeStartResult.DynamicEngines`;
- содержимое исходной папки `Engines` копируется в build/publish output;
- исправлено предупреждение `CS8603` в `EngineRegistry.GetRequired`.

## Формат пакета движка

```text
Engines/
└── MyEngine/
    ├── manifest.json
    ├── MyEngine.dll
    └── зависимости DLL
```

Пример манифеста находится в `Engines/manifest.example.json`.

## Ограничения этого MVP

- конструктор движка пока должен быть публичным и без параметров;
- горячая выгрузка DLL пока не реализована;
- UI списка движков пока не подключён;
- `App.xaml.cs` пока не запускает `PlatformRuntime` автоматически — это отдельный следующий этап.

## Проверка

После применения выполнить сборку. Ожидается:

- `0` ошибок;
- старое предупреждение `CS4014` в `Relay/SerpiumNetManager.cs` может остаться;
- предупреждение `CS8603` из `EngineRegistry.cs` должно исчезнуть.
