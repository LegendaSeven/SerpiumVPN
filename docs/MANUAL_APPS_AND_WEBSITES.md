# Ручные приложения и сайты

На вкладке **Приложения** кнопка **Добавить приложение** открывает каталог с поиском:
**Установленные**, **Запущенные** и **Из файла…**. Последний вариант принимает EXE,
LNK, URL и ClickOnce appref-ms. Обычный ярлык сохраняет название приложения и разрешается в EXE;
ярлыки запуска через Update.exe разрешаются в целевое приложение.
Ручная запись сохраняется даже без ярлыка или обнаруженной сетевой активности.
Новая запись выключена; трафик включается её тумблером. Повторное добавление
сохраняет прежний тумблер. Корзина удаляет ручную запись и её правило, но не файл
программы. Автоопределяемое приложение после этого может остаться в списке.
Службы Windows, системные программы и компоненты VPN выбирать нельзя.

Веб-приложения браузера (например, ярлык TikTok из Яндекс Браузера) показываются
здесь отдельной строкой **Веб-приложение · tiktok.com**. Это одно правило сайта,
видимое также на вкладке **Сайты**: тумблер и удаление синхронизированы.
Общий browser_proxy.exe не добавляется вместо приложения. Правило распространяется
на сайт и его поддомены, включая обычные вкладки браузера; остальные сайты браузера
оно не включает в VPN. Для нового веб-приложения www убирается из основного домена,
поддомены включены. Если правило этого домена уже есть, его тумблер и область
поддоменов сохраняются. Отдельные домены CDN не подбираются автоматически.

Ярлыки читаются без запуска программ и без чтения истории или профиля браузера.
Поддерживаются явный адрес --app=HTTPS-URL, InternetShortcut URL, а также известные
manifest URL, для которых двойной SHA-256 точно воспроизводит Chromium app-id
(включая установленный TikTok). Название ярлыка само по себе не считается адресом.
Если app-id неизвестен и адрес отсутствует, окно добавления запрашивает адрес сайта.
Название сохраняется, а введённый URL нормализуется до домена. Также можно добавить
обычное правило во вкладке **Сайты**.

## Каталог Windows и приложения Store

Каталог объединяет ярлыки меню «Пуск» и рабочего стола, пользовательский AppsFolder,
приложения Store/UWP/MSIX и наблюдаемые процессы текущей учётной записи и сеанса.
Папки на рабочем столе рекурсивно не сканируются. Каталог кэшируется на минуту;
изменения ярлыков ускоряют обновление. Процессы проверяются при обычном обновлении
списка, без чтения их памяти и без запуска приложений.

Основной список отбирает сетевые пользовательские приложения: известные клиенты,
программы с наблюдаемым интернет-соединением и установленные веб-приложения браузера.
Обычные URL-ярлыки справки и сайтов автоматически не добавляются; их можно выбрать вручную.
Поддержка Store/UWP/MSIX
работает по умолчанию с теми же критериями: одного разрешения internetClient или
internetClientServer недостаточно. Для нового неизвестного приложения сначала нужно
запустить его и обратиться к сети либо добавить его вручную. Учитываются также реальные
соединения объявленных исполняемых файлов выбранного приложения Store.
Калькулятор, Безопасность Windows, Терминал и встроенные офлайн-утилиты автоматически
не предлагаются, даже если у них есть сетевое разрешение или служебные обращения к сети.
Исключения привязаны к идентификаторам пакетов, а не к языку интерфейса или всему издателю
Microsoft. Ручной каталог позволяет выбрать другую пользовательскую программу.
Ранее включённые правила остаются видимыми, чтобы их можно было выключить;
сохранённые ручные записи тоже сохраняются. Фильтрация сама не меняет маршруты.
Службы, системные процессы и общие вспомогательные исполнители не превращаются
в отдельные пользовательские приложения.
История интернет-соединений отдельно хранит подтверждение пользовательского приложения
(запись каталога или видимое окно). Старые записи без такого подтверждения перепроверяются;
одной прошлой сетевой активности недостаточно. Фоновые компоненты установки пакетов
WindowsPackageManagerServer, winget и AppInstaller не предлагаются для маршрутизации.

Для Store-приложения сохраняется AUMID конкретного Application из пакета. Используются
его объявленные EXE и процессы, подтвердившие тот же AUMID в текущем пользовательском
сеансе; общие исполнители и службы исключаются. После обновления версии новые пути
сохраняются с прежним тумблером, а при активном VPN обновляются через штатное применение
и откат правил. Сам AUMID не отправляется движку как правило маршрутизации.

Ярлыки игр с протоколом Steam/Epic и ClickOnce не подменяются маршрутом всего лаунчера:
нужно запустить приложение самостоятельно и выбрать его в **Запущенные**. EXE из этого
списка сохраняется как обычное приложение; это не правило по номеру процесса.

Два приложения с одним общим EXE нельзя достоверно разделить текущими правилами по
пути процесса. Такие записи Store показывают ограничение и не предлагают независимый
тумблер. Java/Python/WSL, браузерные профили и общий WebView тоже не получают независимую
маршрутизацию автоматически. Для PWA доступно правило сайта, распространяющееся также
на вкладки. При обновлении обычного переносного приложения с изменением пути может
понадобиться повторное ручное добавление. Полный охват любых Windows-программ не заявлен.

На вкладке **Сайты** можно вставить домен или HTTP/HTTPS-ссылку. Сохраняется
только домен: путь, параметры и фрагмент ссылки отбрасываются. Поддерживаются
международные домены; внутри они хранятся в ASCII/Punycode. Флажок **Включая
поддомены** задаёт область правила. Адреса с логином/паролем, IP и локальные
имена отклоняются. Домен www.example.com сохраняется именно как www.example.com.

Приоритет маршрутов:

1. Существующие исключения локальной сети остаются прямыми.
2. Самое конкретное подходящее правило сайта: включено — VPN, выключено — прямо.
3. Если сайт не указан, применяется тумблер приложения; иначе прямой маршрут.

Удаление сайта возвращает управление оставшимся правилам сайта/приложения.
Изменение подтверждается движком до сообщения об успехе. Старые TCP/UDP-соединения
на противоположном маршруте закрываются только в области изменённого правила.
Программа или браузер создаёт новое соединение; текущая загрузка может прерваться.
При ошибке восстанавливается прежняя запись и политика; при неудаче восстановления
VPN останавливается. Сохранённые правила защищены DPAPI CurrentUser.

Правила маршрутов и DNS обновляются одним атомарно заменяемым набором. Кэш DNS
разделён по резолверам, поэтому прямой ответ не переносится в VPN-резолвер при
переключении. Используются возможности sing-box 1.13.15. Совместимость будущих
движков должна проверяться штатным механизмом обновлений перед заменой.

Ограничения: правило охватывает указанный домен и выбранные поддомены, а не все
внешние ресурсы сервиса. Например, отдельный домен видео/CDN нужно добавить
самостоятельно. Определение имени зависит от DNS reverse mapping и распознавания
протокола sing-box. Зашифрованное имя (ECH), собственный DNS браузера и общие
HTTP/2 или HTTP/3 соединения могут ограничивать точность разделения сайтов.
Если имя соединения неизвестно, применяется правило приложения; неизвестные
соединения других сайтов принудительно не закрываются. Для полного охвата
такого браузера/сервиса можно включить VPN для приложения.
