# HTTPS-подписки и привязка устройства

В поле «Ключ или ссылка» можно вставить HTTPS-ссылку на список ключей или Base64-подписку. HTML-страницы не исполняются. Сам по себе успешный HTTP-ответ не означает, что подписка содержит рабочие серверы.

Некоторые панели возвращают служебные сообщения в виде VLESS-профилей с loopback-адресом и портом 1. Serpium распознаёт такие ответы до сохранения профилей. Вместо попытки подключиться к несуществующему серверу показывается причина: требуется привязка, достигнут лимит устройств, клиент не разрешён или получено другое служебное сообщение.

## Привязка устройства

Поддержаны заголовки Remnawave `x-hwid-not-supported`, `x-hwid-max-devices-reached` и старый `x-hwid-limit`. Некоторые панели устанавливают старый `x-hwid-limit` одновременно с `x-hwid-not-supported`; в этом случае требуется идентификатор, а не освобождение лимита.

При первой необходимости приложение запрашивает согласие. После согласия оно создаёт случайный постоянный идентификатор для конкретного HTTPS-origin (хост и порт). Серийные номера оборудования, MachineGuid, имя компьютера и имя пользователя не собираются и не отправляются. Клиент представляется собственным User-Agent `SerpiumVPN/1.0`.

Согласие и идентификатор сохраняются вместе: наличие файла привязки означает ранее данное согласие. Идентификатор зашифрован Windows DPAPI для текущей учётной записи в `%LOCALAPPDATA%\SerpiumVPN\SubscriptionDevices\*.sdevice`. Права каталога ограничены текущим пользователем и SYSTEM. Имя файла — хеш origin; URL с токеном в файл не записывается. Другому origin назначается другой идентификатор; при переходе на другой origin заголовок не пересылается.

Повторное добавление ссылки использует прежнюю привязку. Ошибка чтения не создаёт новую привязку автоматически. Удаление данных Serpium или переустановка Windows могут потребовать освобождения старого устройства у провайдера. Удаление профиля из списка не удаляет устройство у провайдера. Отозвать локальное согласие можно при закрытом Serpium удалением каталога `SubscriptionDevices`; это не освобождает серверный лимит и при следующем согласии создаст новую привязку.

Файлы привязки исключены из Git и публикации; проверка релиза отвергает их попадание в пакет. Профили продолжают храниться в существующем защищённом хранилище. Импорт по ссылке сохраняет снимок профилей, не выполняет автоматическое обновление подписки и не гарантирует доступность VPN-серверов.

## Проверки

`dotnet run --project Tests/Subscriptions/SubscriptionChecks.csproj -c Release -- <папка-тестов>` проверяет импорт, реальные сочетания служебных заголовков, согласие/отказ, повторную загрузку, перенаправления, отмену, DPAPI и неизменность идентификатора. Используются искусственные ключи и отдельное тестовое хранилище.

Режим `--inspect <HTTPS-ссылка> ...` проверяет текущие ответы без привязки и без сохранения профилей; выводит только число профилей либо код причины. Личные ссылки не следует включать в журналы команд и отчёты.

Спецификация: [Remnawave — HWID device limit](https://docs.rw/features/hwid-device-limit/).
