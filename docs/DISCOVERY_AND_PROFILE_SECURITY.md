# Автообнаружение приложений и защита профилей — 07.10.2026

## Поведение интерфейса

Введённый ключ или ссылка отображаются точками в PasswordBox. Под полем появляется
«Ключ введён · ••••••••». Исправлен двойной отступ шаблона PasswordBox, из-за которого
маска раньше обрезалась по высоте. Длина дополнительной подписи фиксирована; поле
показывает обычную маску PasswordBox. Открытого предпросмотра ключа нет.

При выборе сохранённого профиля поле очищается, в нём показывается
«•••••••• · сохранённый профиль», а под ним — подтверждение сохранения данных.
Расшифрованный ключ не загружается в поле. Новый ввод снимает выбор сохранённого
профиля. После успешного импорта поле очищается. «Стоп» остаётся доступен во время
загрузки, проверки и запуска подключения.

## Автообнаружение

- Изменение ярлыков в личном или общем меню «Пуск» помечает каталог для обновления.
  События объединяются с задержкой 1 секунду; обычный опрос интерфейса — раз в 5 секунд.
  Опрос приостанавливается на время операции подключения.
- Для установок без ярлыка, использующих App Paths, действует резервное обновление
  каталога раз в минуту. Метаданные неизменившихся exe остаются в кэше.
- Новому неизвестному приложению не требуется запись в списке известных клиентов:
  нужны пользовательская точка запуска (регистрация или видимое окно) и замеченная
  сетевая активность. Известные сетевые клиенты могут показываться до первого запуска.
- Для UDP данные движка сопоставляются с владельцем сокета Windows, путём exe,
  SID пользователя и сеансом. Это учитывает приложения, продолжающие работать без
  окна. Один открытый UDP-порт не считается доказательством доступа в интернет.
- Системные процессы, службы, вспомогательные исполняемые файлы и чужие сеансы
  исключаются. Новый пункт появляется с выключенным VPN. Само обнаружение не меняет
  пользовательские правила маршрутизации.
- История содержит пути приложений и время наблюдения, а не содержимое пакетов.
  Наблюдатели каталогов освобождаются при полном выходе из приложения.

Обнаружение пассивное: заранее доказать необходимость интернета для любого ещё
не запущенного приложения нельзя. Для неизвестного приложения без сетевой активности
пункт появится после её наблюдения. Без работающего движка UDP-назначения не выводятся
из одной таблицы локальных сокетов. Приложения без обычной точки запуска могут не попасть
в список. Это ограничение защищает список от фоновых служб и вспомогательных процессов.

## Проверка ввода и хранения

Существующие ограничения импорта сохранены и проверены: поддерживаемые схемы,
ограничение размера и числа профилей, не более двух слоёв Base64, проверка каждого
элемента подписки, HTTPS с проверкой сертификата, ограничение перенаправлений и времени
загрузки, отказ от HTML и перехода на HTTP. Адрес подписки не добавляется в журналы.
Аргументы процесса задаются отдельно; ключ не используется как команда оболочки.

Хранилище profiles.svault использует DPAPI CurrentUser. Конфигурация и метаданные
зашифрованы вместе. Для поиска повторов используется SHA-256 исходного ключа внутри
зашифрованного контейнера; исходный текст ключа отдельно не сохраняется.

Исправления:

1. Размер контейнера проверяется до выделения буфера; чтение выполняется через один
   файловый дескриптор. Повреждённый контейнер отклоняется без сброса или перезаписи.
2. DACL папки заменяется на доступ текущего пользователя и SYSTEM. Старые явные
   разрешения других групп удаляются. Если закрыть доступ не удалось, сохранение
   прерывается. Новые зашифрованные файлы наследуют эти разрешения.
3. Ссылки/reparse points на самой папке Vault и файле контейнера отклоняются.
4. Запись выполняется через зашифрованный временный файл с последующей заменой.
   Буферы конфигураций очищаются, в том числе при отмене ожидания блокировки Vault.
5. Название прямого Xray-профиля проходит очистку от параметров подключения.

## Использование профиля и журналы

Проверка и запуск Xray теперь передают JSON через stdin. Открытый JSON с секретами
не записывается в каталог сборки, LocalAppData или временный каталог. В командной
строке находится только указание stdin. Sing-box уже использовал передачу через stdin.

Необработанные файлы access/error Xray отключены. Диагностика проходит через общий
фильтр: скрываются URI ключей/подписок, UUID, длинные закодированные строки, параметры
секретов с `=`, `:` и в JSON, заголовки Basic/Bearer. Общий фильтр добавлен и в путь
журналирования sing-box. Отмена и тайм-аут завершают дочерний процесс проверки;
зависший процесс, не читающий stdin, не блокирует «Стоп».

Проверка синтаксиса и доступности TCP-сервера сама по себе не означает работающий VPN.
Окончательный статус активного подключения остаётся за существующей проверкой
выбранного исходящего соединения. Выбор, повторный импорт, открытие и удаление профиля
проверены на отдельных тестовых данных.

## Проверки и границы

Проверки выполнены с синтетическими ключами и изолированным Vault: шифрование,
права папки и файла, чтение и обновление профиля, удаление выбранного/последнего,
повреждение и превышение размера, отмена, фильтрация журналов, события установки,
кэш, обнаружение неизвестного UDP-приложения, исключение службы. Проверены реальные
установленные Xray и sing-box на конфигурациях VLESS, VMess, Trojan и Hysteria2.
Реальный Xray запущен с stdin на loopback без внешнего трафика. Жизненный цикл
менеджера дополнительно проверен с локальным mock SOCKS-сервером, включая зависание
при передаче большой конфигурации. Обе темы отрисованы с тестовым ключом.

Эта проверка не является полным независимым аудитом или проверкой всего VPN-трафика.
VPN/TUN пользователя не запускался, личная подписка не запрашивалась. DPAPI не защищает
от вредоносной программы с правами того же пользователя или администратора. Рабочему
движку нужны расшифрованные данные в памяти; неизменяемые строки .NET нельзя надёжно
обнулить. Буфер обмена пользователя не очищается. Старые журналы, дампы и резервные
копии не анализировались на наличие исторических секретов. Явные параметры проверки
сертификатов VPN-сервера в импортированном профиле не изменялись.
